Xử lý tối ưu memory leak khi dùng WebSocket kết hợp TanStack Query trong Next.js 19

NH
Nguyễn HạnhHọc viên tích cực • Lớp FE-Adv-04 • Lộ trình Fullstack Senior Transition
♧ 18

Chào Thầy cô và các bạn, mình đang hoàn thiện module đồ án Capstone Real-time Crypto & Stock Dashboard sử dụng App Router trên Next.js 19 kết hợp TanStack Query v5 để đồng bộ state client-side.

Vấn đề xuất hiện khi người dùng chuyển đổi tab liên tục giữa các mã chứng khoán (các component biểu đồ unmount và remount tức thì). Mình phát hiện memory consumption trên Chrome DevTools Heap Snapshot tăng đột biến từ 42MB lên 280MB chỉ sau 3 phút điều hướng.

Khi kiểm tra chi tiết, các WebSocket listeners vẫn còn bị giữ lại tham chiếu bởi closures trong React hooks, khiến instance của query observer không giải phóng:

🔴 hook/useSocketQuery.ts (Đoạn mã gây lỗi) ▣ Sao chép
export function useSocketPriceFeed(symbol: string) {
  const queryClient = useQueryClient();
  useEffect(() => { // ⚠ Bug: Socket instance bị capture trong closure
    const socket = getGlobalSocket();
    socket.on('ticker', (payload) => {
      queryClient.setQueryData(['price', symbol], payload);
    });
    // TODO: cleanup listener khi unmount
  }, [symbol]); // Missing cleanup function return
}

Lý do gây ra tình trạng Memory Leak nghiêm trọng này có 2 nguyên nhân cốt lõi: sự kiện đăng lại trong Bus Socket callback và đóng bộ hóa sai thời điểm với React State.

Giải pháp tối ưu chuẩn Senior: Sử dụng API mới useSyncExternalStore để React 18+ tự tiếp tục tối ưu hóa trên React 19.

✓ hook/useOptimizedSocketFeed.ts (Refactored Solution) ▣ Sao chép Code
import { useSyncExternalStore } from 'react';
import { socketManager } from './socketManager';
export function usePriceFeed(symbol: string) {
  const subscribe = (callback: () => void) => {
    return socketManager.subscribeToTicker(symbol, callback);
  };
  return useSyncExternalStore(subscribe, getSnapshot, getSnapshot);
}
