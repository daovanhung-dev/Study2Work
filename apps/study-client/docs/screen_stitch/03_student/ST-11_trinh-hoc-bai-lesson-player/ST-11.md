### Discrepancies cần giữ rõ

1. Inventory gọi đây là lesson player nhưng screenshot/HTML chỉ hiển thị “Nội dung bài học hiện chưa sẵn sàng.” Không có loaded, playing, paused, progress-saving hoặc finished interface.
2. ST-10 inventory/DD gọi #24 trước handoff; ST-11 inventory cũng gọi #24 khi mở player. Chưa rõ màn nào sở hữu lần đọc, dữ liệu nào được handoff và có cần gọi hai lần không.
3. AC-15 diagram mô tả #26 trước #27 trước render; ST-11 inventory nói #26 lazy và #27 sau completed; không có source để chọn một orchestration.
4. API #26 khai báo `ApiEnvelope<Lesson>` dù tên/use case là resources. Reusable `Resource` là schema khác; không tự thay response.
5. API #25 yêu cầu `position`, nhưng candidate `lesson_progress` không có cột này; range, unit, state, update identity, autosave/throttle, aggregate và retry chưa chốt.
6. Candidate `resources` DDL không có visibility; URL stored-vs-signed và access policy không rõ. Không mở resource URL từ UI theo suy đoán.
7. ST-10/ST-09 hiện chưa truyền lessonId tới ST-11; current client route/runtime cũng không có.
8. HTML có các path href trực tiếp nhưng Study Web router/serving/deployment chưa xác minh; path string trong HTML không phải runtime navigation evidence.

## B. Mô tả luồng hoạt động tổng thể

### Expected flow theo inventory và AC-14/15

1. Student được điều hướng tới `/student/lessons/:lessonId` với lessonId đã chọn. Inventory yêu cầu Student; API catalog yêu cầu Bearer JWT/role Student. Route, auth guard và lessonId handoff chưa được wired.
2. Khi lesson context hợp lệ, inventory gọi GET #24 để nạp `Lesson`. Tuy nhiên ST-10 cũng mô tả GET #24 trước handoff; Product/FE phải chỉ định owner của request và có/không handoff response/cache. Không giả định cache hay gọi trùng.
3. #24 response theo catalog là `ApiEnvelope<Lesson>`: `id`, `course_id`, `title`, `content?`, `video_url?`, `order`, `status`. Chỉ response thành công qua authorization mới có thể cung cấp lesson content/media; `content`/`video_url` optional, null serialization và LessonStatus chưa chốt.
4. Nếu media/player được thiết kế, người học có thể xem nội dung; nhưng asset hiện không có media element, control, URL binding, renderer, transcript/captions hoặc buffering model. Không tự chọn player vendor, autoplay, seek behavior, URL signing hay media token.
5. Inventory yêu cầu GET #26 lazy. Trigger UI chưa hiện diện. #26 catalog trả `ApiEnvelope<Lesson>` trong khi ý nghĩa là resources; type/cardinality/order/empty state/visibility/URL policy chưa được duyệt.
6. Inventory yêu cầu PATCH #25 “khi có biến cố progress hợp lệ”. Catalog body là `position:int32!`, `percent:int32!`, `completed:boolean!`; tần suất, event, đơn vị position, range/rounding, throttle, autosave, retry, dedup và state precedence chưa rõ. AC-14 nói cập nhật lesson progress và course aggregate; không có formula/transaction/schema nguồn cho aggregate.
7. AC-14 diagram nêu `completed = YES` → mark `COMPLETED`, `NO` → giữ `IN_PROGRESS`. Không có completion trigger/threshold trong UI hoặc contract. Inventory gọi GET #27 sau completed; tie-break, bài cuối, 404-vs-empty và navigation policy còn mở.
8. Expected navigation liên quan ST-09/ST-12/ST-13/ST-17 theo inventory. Asset chỉ có link về `/student/courses`, `/student` và `/student/progress`, không có ST-12/resources, quiz, assignment hay next-lesson control.

#### Security decisions and handling

- API catalog declares Student Bearer authentication for #24–#27. The API DD open questions still require the owner to define the entitlement predicate and direct-call behavior for each endpoint; a prior client call to #22 or #24 is not evidence that a later independent request is authorized.
- Keep protected content/media out of UI until a successful #24 response under the approved access policy. Public curriculum API #09 is not a protected-content substitute; do not rely on a client route guard as a security boundary.
- Do not assume `video_url` is signed, public, stream-safe or allowed outside the authorized player; the catalog merely marks it optional URI.
- Do not assume #25 response carries progress or a safe position. Catalog response is Lesson and the position storage is unresolved.
- Do not treat absent resources, terminal next lesson, 403, 404, expired session or network error as interchangeable; mapping is open.
- Do not use either checked-in DDL artifact as live schema or combine their identifiers. Legacy `lesson_progress` has nullable user/lesson IDs and no lesson `position` or user/lesson unique key; V1-PILOT `lesson_progress_facts` is UUID/enrollment-based and also has no `position`/`percent`. Neither artifact provides `resources.visibility`.
- Do not create a token/session field, player URL, signed URL, cache key, retry protocol or telemetry event without a canonical source.

## G. Ghi chú UI, accessibility và design system

- Source uses Plus Jakarta Sans via Google Fonts, max width 1440px, fixed 64px header, responsive gutters and a 48px minimum-height CTA. Study UI guide targets Inter/system without remote font import, content width around 1120px and semantic ocean tokens. Record as design discrepancy; preserve the supplied screenshot/HTML.
- CTA and navigation links have visible text labels. Material Symbol spans include text tokens such as `arrow_back`, `chevron_right`, and `play_lesson` without explicit `aria-hidden`/accessible-name attributes; verify announcement behavior when the app is implemented.
- Links include hover styles but no explicit `focus-visible` utility. Do not assume keyboard focus is absent; verify visible focus and tab order in the real runtime.
- The static fallback has a correctly visible H1 and text message, but there is no dynamic status announcement, loading/live region or player keyboard contract.
- Verify reflow at 320px, browser zoom, focus visibility, contrast, target size, screen-reader names, captions/transcript and reduced-motion behavior when actual player/UI is designed. Do not claim WCAG conformance from the asset.
