## 2. Current API/data trace

### Hydrate và refresh — API #49

`GET /api/v1/mentor/courses/{course_id}/content` không có body/query. Shared guard kiểm tra Bearer/JWT và role `MENTOR` trước DB; sau đó parse signed int64, đọc course, so sánh numeric JWT subject với `courses.mentor_id`, rồi lấy các dòng `contents` có `deleted_at IS NULL`, sắp theo `parent_id NULLS FIRST`, `content_order`, `id`.

Response success là `ApiEnvelope<Content[]>` với mỗi item `{id:int64, course_id:int64, content_type:string, title:string, payload:object, status:string, parent_id:int64|null, order:int32}`. Response là collection phẳng để client dựng cây; không có endpoint Content detail hoặc `canPublish/canDelete` field. #49 trả mọi status đang hoạt động để Mentor quản lý; `data:[]` hợp lệ.

Lỗi hiện tại: 401 auth; 403 role/direct-owner mismatch; 404 course path sai/không có course; 500 query, projection, duplicate/missing-parent/cycle integrity. Không có partial-tree response. Client edit flow phải tìm chính xác `data[].id == contentId` và xác nhận cùng `course_id`; không dùng giá trị mẫu của screenshot nếu không tìm thấy.

### Publish/unpublish — API #52 current source và contract

| Hạng mục | Current route/module source | Catalog/AC/API DD |
|---|---|---|
| Method/path | `PATCH /api/v1/mentor/content/{content_id}/publish` | Cùng route. |
| Request | Strict JSON `{published:boolean}`; bool strict, field thừa bị cấm. | Catalog #52 và AC-22 chỉ nêu path, không có body/action. Body là `DERIVED`; #52 DD vẫn `Draft — Needs Confirmation`. |
| Auth/access | Bearer + role `MENTOR`; khóa Content/Course rồi yêu cầu JWT numeric `sub == courses.mentor_id`. | AC-22 nói có quyền quản lý course; assignment/co-owner mapping chưa được source xác nhận. |
| Local transition fallback | `APPROVED → PUBLISHED` khi `published=true`; `PUBLISHED → APPROVED` khi `published=false`. Target giống trạng thái hiện tại là no-op và vẫn trả 200. Các trạng thái khác trả 422. | Catalog chỉ nói validate readiness; không định nghĩa enum, readiness, publish vs approval hay unpublish target. |
| Side effect | Chỉ đổi `contents.status`; không đổi payload/order/parent, không ghi `content_versions` hay audit row. | AC-22 nói update publication status; AC-33 gộp `APPROVED/PUBLISHED` khi Admin approve nên lifecycle đang mâu thuẫn/mở. |
| Success | HTTP 200 `DESIGN_RESOURCE_UPDATED`, `data` là Content projection. | `ApiEnvelope<Content>`. |

View trace: route → `publish_content` → shared Mentor guard → parse signed-int64 Content ID → `LOCK_MENTOR_CONTENT` (`FOR UPDATE OF content, course`, active row) → owner check → so sánh current/target status → conditional `UPDATE_PUBLICATION_STATUS` với expected status hoặc giữ row hiện tại cho same-target → validate Content projection → commit → response. Lookup/update/mapping/commit lỗi rollback an toàn và trả 500. Body/path/current state không hợp lệ trả 422 hoặc 404 theo nhánh; owner mismatch 403. Không có 409/version token.

`APPROVED` hiện chỉ là gate theo status, không kiểm tra payload completeness, asset, ContentType, revision, child readiness hoặc permission flag. Không suy ra rằng đổi status sẽ làm nội dung “hiển thị cho tất cả học viên”: API DD ghi rõ readiness/current revision và tác động tới public reader chưa được định nghĩa. `#52` source có target-idempotency cho retry cùng body, nhưng body và state machine chưa được duyệt.

### Xóa — API #53 current source và contract

| Hạng mục | Current route/module source | Catalog/AC/API DD |
|---|---|---|
| Method/path | `DELETE /api/v1/mentor/content/{content_id}` | Cùng route; path int64, không body/query. |
| Auth/access | Bearer + role `MENTOR`; khóa active Content/Course rồi so sánh JWT subject với `courses.mentor_id`. | AC-22 yêu cầu quyền quản lý course; direct owner là current fallback, không phải policy được duyệt. |
| Guards | Current `status == PUBLISHED` trả 422 trước khi truy vấn dependency. Nếu không PUBLISHED, query chỉ kiểm tra **direct child** có cùng course, `parent_id=content_id`, `deleted_at IS NULL`; có child thì 422. Các status không phải PUBLISHED khác được source cho phép qua guards này. | Catalog yêu cầu “nếu được phép; kiểm tra dependency”, nhưng không liệt kê dependency hoặc status eligibility. Child/PUBLISHED rules là `DERIVED`. |
| Mutation | `UPDATE contents SET deleted_at=CURRENT_TIMESTAMP`; không hard-delete, cascade, reparent, đổi status, ghi audit/version hoặc kiểm tra submission/asset/progress. | AC-22 chỉ mô tả DELETE/soft delete rồi reload tree; retention, audit, dependency ngoài cây và queue withdrawal còn mở. |
| Success | HTTP 200 `DESIGN_RESOURCE_DELETED`; `data={id:int64, status:"deleted", deleted_at:datetime}`. | `ApiEnvelope<DeleteResult>`. Response không trả `course_id`. |

View trace: route → `delete_content` → shared Mentor guard → parse signed-int64 ID → lock Content/Course where active → owner check → reject PUBLISHED → query active direct child → soft-delete timestamp → validate `DeleteResult` → commit → success envelope. Missing/already deleted/invalid ID 404; role/auth 401/403; owner mismatch 403; PUBLISHED/active child 422; query/projection/commit failure 500 with rollback. Vì #53 không thay `status`, response literal `deleted` là DeleteResult status, không phải ContentStatus.

Sau khi `deleted_at` được ghi, #49 loại target khỏi collection. Lặp DELETE lên tombstone trả 404 từ active-row lookup. Nếu request timeout sau commit, client không thể coi lần DELETE kế tiếp là cùng success; retry policy chưa có contract. Candidate reconciliation là GET #49 bằng `courseId` đã giữ lại, không gửi lại action tự động.

### Persistence boundary và cây Content

- Local `contents` được khai báo trong legacy `DB.sql` và migration 006; migration 007 thêm `content_versions`. Đây là checked-in schema evidence, không xác nhận live database/deployment. Không dùng UUID V1-PILOT `content_blocks` thay cho legacy BIGINT Content.
- #52 cập nhật status của row hiện tại, không chọn version từ `content_versions`. #53 chỉ cập nhật `deleted_at`, giữ row và mọi snapshot; không xóa lịch sử.
- #53 guard chỉ nhìn active direct children. Đây không phải kiểm tra dependency toàn hệ thống: không thấy query với lesson/assessment/asset/submission/progress/review queue hoặc các tham chiếu JSON payload. Ngoài ra #49 loại mọi tombstone rồi từ chối cây có parent không hiện diện; source #53 không kiểm tra descendant sâu bị tách bởi một child đã soft-delete. Đây là khoảng trống suy ra từ hai source path, cần owner xác nhận trước khi tuyên bố cây luôn hợp lệ sau delete.
- API #52/#53 test files hiện có là fake-session HTTP tests. Context Study Server ghi nhận focused suites trước đó lần lượt 27 và 18 tests pass; phiên này chỉ đọc test source/context, không chạy test. Fake rows không xác nhận PostgreSQL lock/FK, migration live hoặc runtime deployment.

## 5. Detailed event specification

### ME08-EV-01 — Mở ME-08 và xác định Content/course context

- **Trigger:** open proposed `/mentor/content/:contentId/actions` from ME-06, or direct route entry.
- **Input:** `contentId` path; expected `courseId` and selected Content from ME-06 route/context. The proposed route only includes Content ID, and there is no current client navigation state.
- **Processing:** parse route ID as an integer candidate without treating a malformed ID as create/new; require an authenticated Mentor session before protected data is shown. Obtain the `courseId` from an agreed navigation contract. If absent, block hydration/mutation; do not guess course from an unscoped Content endpoint because no detail endpoint exists.
- **Output:** `loading` until #49 returns an exact Content; no sample title/status should appear as loaded data. Route resolution and session UX are not wired.
- **Exceptions:** malformed/missing route value and direct-link return behavior have no client contract; API #52/#53 map malformed int64 path to 404 after the shared auth guard.

### ME08-EV-02 — Load selected Content with GET #49

- **Trigger:** route has `contentId` and resolved `courseId`.
- **Request:** `GET /api/v1/mentor/courses/{course_id}/content`, `Authorization: Bearer <token>`, no body/query.
- **Steps:** (1) send course ID only to the course-scoped route; (2) current API authenticates MENTOR and direct owner before Content query; (3) read all active Content rows and validate flat tree; (4) client finds exact `id == contentId`, verifies `course_id`, then maps title/type/status/parent/order; (5) render action context and keep API-provided status raw until status labels are approved.
- **Success:** HTTP 200 `DESIGN_RESOURCE_RETRIEVED`; `data:[]` is valid as a course tree but yields `not-found` for a selected Content ID. No `canPublish/canDelete` field exists.
- **Errors:** 401 auth; 403 role/owner; 404 invalid or missing course; 500 query/projection/tree-integrity. No partial list. Exact selected Content absent from a successful collection is a UI not-found result, not a new API code.
- **Side effect/cache:** GET is read-only. Cache policy and request cancellation are not implemented.

### ME08-EV-03 — Confirm publish using PATCH #52

- **Trigger:** explicit user confirmation for publish. In current source HTML the publish button is disabled; the event is a candidate only.
- **Preconditions:** exact Content loaded; Mentor passes server access check; Content transition and readiness policy approved; destructive/public confirmation text and destination behavior agreed.
- **Request:** `PATCH /api/v1/mentor/content/{content_id}/publish`; Bearer JWT; current source body `{ "published": true }`. This body is strict/current-source DERIVED and absent from catalog/AC, so it is not an approved client contract.
- **Current processing:** guard MENTOR → parse Content ID → lock active Content/Course → direct-owner check → require current `APPROVED` (unless already `PUBLISHED`) → change only `contents.status` to `PUBLISHED` → validate Content response → commit. Source does not validate payload/assets/revision beyond status.
- **Success:** 200 `DESIGN_RESOURCE_UPDATED` + Content. Prevent duplicate UI submits while processing, then revalidate #49. The text “Hiển thị cho tất cả học viên” is not proven by the mutation source.
- **Errors:** 401; 403 role/direct owner; 404 invalid/missing/deleted Content; 422 strict-body error or unsupported current status; 500 lookup/update/projection/commit. No 409 or version selector.
- **Retry/partial failure:** repeating the same target returns current Content without another UPDATE in local source. Contract body/idempotency is unapproved. If mutation succeeds but #49 refresh fails, preserve `success-await-refresh` separately from mutation failure.

### ME08-EV-04 — Confirm unpublish using PATCH #52

- **Trigger:** explicit unpublish action if Product approves one. The screenshot has no unpublish button, so there is no current element/click handler.
- **Preconditions/input:** exact Content loaded and currently PUBLISHED; user selected target state `published=false`. Do not implement as a blind toggle because path-only catalog cannot identify intent.
- **Request:** same PATCH path and strict current-source body `{ "published": false }` (DERIVED, not approved).
- **Current processing:** lock active Content/Course → direct-owner check → if already APPROVED return the same row/no-op; otherwise require PUBLISHED → update only status to APPROVED → validate response → commit.
- **Success/errors:** 200 `DESIGN_RESOURCE_UPDATED` + Content; 401/403/404/422/500 as #52. If Content is PENDING_REVIEW, DRAFT, REJECTED or another status, local view rejects 422. This is not the catalog’s finalized lifecycle.
- **Output:** refresh #49. No version is changed and no audit row is written by this handler.

### ME08-EV-05 — Confirm deletion using DELETE #53

- **Trigger:** click Delete then an explicit confirmation step if that UX is approved. Current button is disabled and no confirm dialog exists.
- **Request:** `DELETE /api/v1/mentor/content/{content_id}`, Bearer JWT, no request body/query. Do not add status, course ID, dependency list or version to the body.
- **Current processing:** guard MENTOR → parse ID → lock active Content/Course → direct-owner check → if exact status is PUBLISHED return 422 before child lookup → check for active direct Content child → if one exists return 422 → write `deleted_at=CURRENT_TIMESTAMP` → validate DeleteResult → commit.
- **Success:** 200 `DESIGN_RESOURCE_DELETED`; `data={id,status:"deleted",deleted_at}`. Do not call it a Content `status=DELETED`; current source leaves `contents.status` as-is and filters tombstone via `deleted_at`.
- **Errors:** 401; 403 role/owner; 404 malformed/missing/already-soft-deleted ID; 422 PUBLISHED or active direct child; 500 query/projection/commit. Exact eligibility of other statuses and dependencies beyond direct children is DERIVED/open.
- **After success:** use preserved `courseId` to GET #49, where the tombstone is omitted, then return to ME-06. The DeleteResult itself cannot supply course ID. If #49 refresh fails, report delete success with refresh pending; do not issue automatic DELETE retry because a repeated tombstone lookup returns 404.
- **Non-atomic sequence:** source suggests unpublish PUBLISHED via #52 before delete via #53, but those are separate commits. If delete is later blocked by an active child, Content remains APPROVED. Do not chain both mutations automatically until the lifecycle/policy is approved.

### ME08-EV-06 — Return to ME-06

- **Trigger:** click #37 or return after a completed mutation.
- **Expected input:** preserve `courseId`, route context and optionally selected node ID; refresh #49 before showing the tree after mutation.
- **Current:** CTA is `href="#"`; no router/state/cache exists. No dirty form is present, but confirmation/return semantics for a failed mutation are not defined.
- **Output:** candidate destination `/mentor/courses/:courseId/content` from ME-06 inventory; not a current route implementation.

### ME08-EV-07 — Header, breadcrumb, policy and footer links

- **Trigger:** click #1–#6, #14, #42, #44–#46.
- **Current:** all anchors target `#`; `data-path` is inert metadata in HTML and there is no click handler/router. Profile at #4 is static.
- **Expected:** destination map/course context must come from approved navigation design. These links do not call #49/#52/#53 and must not mutate Content.

### ME08-EV-08 — Render impact, audit and protection copy

- **Trigger:** screen render of #8, #11, #13, #16, #23–#29, #33, #36, #38–#41, #43.
- **Current:** each value is static. #49 returns no impact/audit/environment metrics; #52 does not write audit/version; #53 does not query student progress/submissions/assets.
- **Expected:** no API event can be specified from available contracts. Keep these regions labeled design-only or replace them with approved source-backed copy before implementation.

Do not claim retention of learner progress or certificate recalculation unless a source-backed contract covers those records.

**Responsive/accessibility:** Current HTML marks buttons disabled and includes `aria-disabled`; no action dialog, focus trap, live-region response, confirmation focus management, error association or loading state is wired. ## 8. Acceptance criteria

1. ME-08 obtains `contentId` plus course context from an approved ME-06 handoff and hydrates only the matching Content from #49; it does not invent a detail endpoint or trust sample data.
2. Publish and unpublish intent are explicit target actions. #52 body/state/readiness contract is approved before implementation; supported response/errors are mapped as documented.
3. Delete confirmation accurately states the approved dependency policy. Current #53 source facts (PUBLISHED guard, active direct-child guard, soft-delete result) stay distinct from unapproved effects and missing dependency checks.
4. Mutations remain separate. If product requires unpublish then delete, intermediate success and later delete failure are represented; no assumption of atomicity.
5. After mutation, #49 is reloaded with preserved `courseId`; #53 response is not expected to provide it. Mutation success and refresh error are separate states.
6. 46 marker IDs match one DD element each and the JSON/SVG/image. Every visible link/button is either source-backed or explicitly static/blocked.
7. Current server auth, request, side effects, response, errors and test-source limits are traced; there is no claim of Study Web, deployed API or live DB runtime verification.
