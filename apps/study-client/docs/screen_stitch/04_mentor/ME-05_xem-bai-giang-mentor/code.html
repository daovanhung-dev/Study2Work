Trong React 19, hệ thống React Compiler đảm nhận việc tự động áp dụng fine-grained memoization đối với các JSX elements, values, và functions nội bộ mà không đòi hỏi nhà phát triển phải thủ công cấu hình useMemo hoặc useCallback rải rác.

Tuy nhiên, khi làm việc với Non-React State Containers (như WebSockets, RxJS Subscriptions, IndexedDB listeners hoặc Redux/Zustand core), nếu kết nối trực tiếp qua useEffect + useState sẽ gây ra hiện tượng Tearing (xung đột nhất quán dữ liệu trong Concurrent Rendering) và rò rỉ bộ nhớ (Memory Leak) nghiêm trọng khi tác vụ unmount diễn ra lúc microtask còn tồn đọng.

lightbulb
Nguyên lý cốt lõi: Quy tắc Immutability cho GetSnapshot Hàm getSnapshot phải trả về giá trị bất biến (primitive hoặc cùng cached reference). Nếu trả về object mới mỗi lần gọi, React 19 sẽ lặp vô hạn và văng lỗi cảnh báo hiệu suất cực hạn.
useNetworkStore.ts
TypeScript 5.4 / React 19.x 
import { useSyncExternalStore } from 'react';

// 1. Khai báo external store singleton độc lập ngoài React tree
const networkStore = {
  status: navigator.onLine,
  listeners: new Set<() => void>(),
  
  subscribe(callback: () => void) {
    networkStore.listeners.add(callback);
    const handleUpdate = () => {
      networkStore.status = navigator.onLine;
      callback();
    };
    window.addEventListener('online', handleUpdate);
    window.addEventListener('offline', handleUpdate);

    return () => {
      networkStore.listeners.delete(callback);
      window.removeEventListener('online', handleUpdate);
      window.removeEventListener('offline', handleUpdate);
    };
  },

  getSnapshot(): boolean {
    return networkStore.status;
  }
};

// 2. Hook tuân chuẩn Concurrent React 19 - Zero memory leak
export function useOnlineStatus() {
  return useSyncExternalStore(
    networkStore.subscribe,
    networkStore.getSnapshot,
    () => true // Server snapshot fallback cho SSR/Next.js App Router
  );
}
