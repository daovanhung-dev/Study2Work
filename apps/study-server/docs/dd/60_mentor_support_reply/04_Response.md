## Ví dụ thành công

~~~json
{
  "success": true,
  "businessCode": "DESIGN_RESOURCE_UPDATED",
  "message": "Support reply saved.",
  "data": {
    "id": 60001,
    "course_id": 120,
    "student": {"id": 2042, "full_name": "Nguyễn An"},
    "status": "OPEN",
    "messages": [
      {
        "id": 90001,
        "author": {"id": 1001, "full_name": "Trần Mentor"},
        "content": "Mình đã gửi hướng dẫn xử lý cho bạn.",
        "attachments": [
          {"id": 81001, "name": "guide.pdf", "url": "https://example.invalid/guide.pdf", "content_type": "application/pdf", "size_bytes": 4096, "status": "UPLOADED"}
        ],
        "created_at": "2026-10-25T08:30:00Z"
      }
    ],
    "created_at": "2026-10-25T08:20:00Z"
  },
  "meta": {},
  "traceId": "123e4567-e89b-42d3-a456-426614174000"
}
~~~

Example IDs, user and timestamps are illustrative. JSON data reflects the current local fallback; it does not prove live rows or URL reachability.

## Ví dụ lỗi

~~~json
{
  "success": false,
  "businessCode": "DESIGN_VALIDATION_ERROR",
  "message": "Dữ liệu đầu vào không hợp lệ.",
  "data": null,
  "meta": {"fieldErrors": [{"field": "message", "code": "VALUE_ERROR", "message": "Message must contain non-whitespace text."}]},
  "traceId": "123e4567-e89b-42d3-a456-426614174000"
}
~~~

Invalid path/body/ref syntax uses catalog 422. Unresolvable or out-of-scope upload IDs use generic catalog 404.
