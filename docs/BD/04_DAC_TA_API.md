# 04. Đặc tả API canonical V1-PILOT

## 1. Phạm vi và quyền sở hữu

Tài liệu này là nguồn định nghĩa duy nhất cho API, realtime contract, webhook, business code và event contract của Study2Work V1-PILOT. Tài liệu mô tả **thiết kế đích**, không cam kết các ứng dụng prototype hiện tại đã triển khai đủ. OpenAPI, JSON Schema và mã nguồn phải được sinh hoặc đối chiếu từ tài liệu này; khi khác nhau, thay đổi nghiệp vụ phải được phê duyệt và cập nhật tài liệu trước.

Ba origin độc lập:

| Service           | Public origin                       | Internal origin                             | Database sở hữu   |
| ----------------- | ----------------------------------- | ------------------------------------------- | ------------------- |
| Platform Identity | `https://identity.study2work.vn`  | `https://identity-internal.study2work.vn` | Identity PostgreSQL |
| Study             | `https://study-api.study2work.vn` | `https://study-internal.study2work.vn`    | Study PostgreSQL    |
| Work              | `https://work-api.study2work.vn`  | `https://work-internal.study2work.vn`     | Work PostgreSQL     |

Không service nào query hoặc ghi database của service khác. Public API dùng `/api/v1`; service-to-service dùng `/internal/v1`. Đường dẫn health và JWKS là ngoại lệ được nêu rõ. API internal chỉ nhận mTLS ở private network, service JWT ES256 có `iss`, `aud`, `sub`, `jti`, `iat`, `exp <= 5 phút`, chữ ký request và chống replay.

## 2. Quy ước bắt buộc

### 2.1 Dữ liệu và envelope

- JSON dùng `camelCase`; database dùng `snake_case`; ID là UUID v7 biểu diễn chuỗi; thời gian là ISO-8601 UTC có hậu tố `Z`; tiền là số nguyên VND (`amountVnd`), không dùng số thực.
- Content-Type mặc định `application/json; charset=utf-8`. Upload đi thẳng object storage bằng signed URL; API không nhận multipart file lớn.
- Thành công và lỗi đều dùng đúng một envelope:

```json
{
  "success": true,
  "businessCode": "COURSE_ENROLLED",
  "message": "Đăng ký khóa học thành công.",
  "data": {},
  "meta": {
    "page": 1,
    "pageSize": 20,
    "totalItems": 1,
    "totalPages": 1,
    "nextCursor": null
  },
  "traceId": "0198a4c0-2d18-7a42-a82a-32f56e93bd10"
}
```

- `data` là object, array hoặc `null`; `meta` luôn là object. Lỗi field-level đặt `meta.fieldErrors = [{field, code, message}]`; không trả stack trace, SQL, token, secret hay thông tin tồn tại của email ở API công khai.
- HTTP status: `200/201/202/204` thành công; `400` cú pháp/validation; `401` chưa xác thực/token không hợp lệ; `403` thiếu quyền/tenant/suspended; `404` không tồn tại **hoặc không thuộc scope**; `409` conflict/invariant; `412` `If-Match` sai; `422` hợp lệ cú pháp nhưng không thể xử lý; `429` rate limit; `503` dependency tạm thời. `Retry-After` có ở `429/503` khi biết.

### 2.2 Auth, permission và tenant

- Public catalog có thể anonymous. API còn lại nhận `Authorization: Bearer <access-token>` do Identity phát hành, access token 15 phút, JWT ES256 kiểm qua JWKS có cache và refresh khi gặp `kid` mới.
- Gateway/API kiểm `iss`, đúng `aud` (`study-api`, `work-api` hoặc `study-evidence`), `exp`, `nbf`, `jti`, `sid`, `authVersion`; tiếp đó kiểm projection account chưa suspended/deleted.
- Global role chỉ là coarse gate. Study permission lấy từ local RBAC. Work permission lấy từ membership đang hoạt động của `enterpriseId`/`universityId` trong path hoặc server-side context; không tin `tenantId`, `role` do body truyền.
- Tài khoản đặc quyền phải có claim MFA còn hiệu lực không quá 12 giờ. Tác vụ tài chính, break-glass, đổi role, publish và export audit yêu cầu step-up không quá 15 phút.
- Mọi query tenant phải có predicate tenant đầu tiên và dùng composite index/constraint chứa tenant ID. Không phân biệt lỗi “không tồn tại” và “khác tenant”.

### 2.3 Pagination, filter, cache và rate limit

- Catalog/admin list dùng `page` từ 1, `pageSize` mặc định 20, tối đa 100; sort nằm trong allowlist. Chat, notification, audit dùng opaque signed cursor, `limit` mặc định 30, tối đa 100; cursor khóa filter và chiều sort.
- Search text chuẩn hóa Unicode, tối đa 200 ký tự. Date range tối đa 366 ngày trừ export vận hành. Filter không có trong catalog bị từ chối, không silently ignore.
- Public catalog cache Redis/CDN 60 giây, `ETag` theo published revision; profile/private/ATS/payment không cache shared. GET cá nhân có `Cache-Control: private, no-store` nếu chứa PII.
- Baseline: anonymous 60 request/phút/IP; authenticated 300/phút/user; login 10/15 phút/IP và 5/15 phút/email hash; register/reset/resend 3/giờ/email hash; candidate search 60/phút/member; chat send 30/phút/conversation; AI 10 job/giờ/user hoặc entitlement thấp hơn. Rate key không lưu raw email.

### 2.4 Idempotency, optimistic concurrency và transaction

- Header `Idempotency-Key` là UUID/random 16–128 ký tự, scope theo principal + method + normalized path, giữ response 24 giờ. Cùng key khác request hash trả `IDEMPOTENCY_KEY_REUSED`; request đang chạy trả `REQUEST_IN_PROGRESS`.
- Bắt buộc cho register, enroll/switch, submit assessment, publish, apply, payment order/refund, interview mutation và chat send. Consumer/webhook có idempotency vô thời hạn nghiệp vụ theo `providerEventId`/`eventId`.
- `If-Match: "<version>"` bắt buộc cho draft/editor/review/profile quan trọng. Sai version trả `412 VERSION_CONFLICT` kèm current version và safe diff metadata.
- Transaction chỉ bao phủ một database. Side effect ngoài DB dùng transactional outbox. Không gọi HTTP dependency trong transaction; saga/worker retry exponential jitter và DLQ sau số lần quy định.
- Bảng append-only gồm audit, history, payment webhook/ledger, AI review, application snapshot, message event và outbox. Không hard-delete/cascade làm mất lịch sử.

### 2.5 Quy ước mô tả endpoint

Mỗi dòng catalog dưới đây là một contract đầy đủ theo các cột:

1. **Actor/quyền**: principal và permission bắt buộc.
2. **Input/validation → output**: path/query/body, giới hạn và payload trả về.
3. **Xử lý, dữ liệu**: thứ tự xử lý, bảng đọc/ghi, predicate/join/index, lock/transaction.
4. **Vận hành**: idempotency, event, audit, cache/rate-limit.
5. **Lỗi**: business code đặc thù; các lỗi chung ở trên vẫn áp dụng.
6. **Màn hình**: ID màn hình canonical được sở hữu tại `05_DAC_TA_MAN_HINH.md`; `SYSTEM` là worker/provider không có UI.

Ký hiệu `R:` bảng đọc, `W:` bảng ghi, `L:` row/advisory lock, `TX:` transaction. Tên bảng là canonical và được ánh xạ sang `TBL-*` tại `03_THIET_KE_CO_SO_DU_LIEU.md`.

### 3.2 Thuật toán refresh reuse

1. Hash refresh token bằng keyed SHA-256; không log raw token.
2. Mở transaction, `SELECT ... FOR UPDATE` đúng token và session family.
3. Token hợp lệ, chưa dùng: đánh dấu `used_at`, tạo child token hash, commit rồi ký access/refresh mới.
4. Token đã dùng hoặc có `replaced_by_token_id`: xem là reuse, revoke mọi token/session cùng family, tăng `auth_version`, ghi security audit và outbox trong cùng transaction; không phát token mới.
5. Hai refresh đồng thời: chỉ transaction đầu thành công; transaction sau đi nhánh reuse. Client phải single-flight refresh và đăng nhập lại khi nhận `REFRESH_TOKEN_REUSE_DETECTED`.

### 4.5 Luồng transaction Study trọng yếu

**Đổi primary path (`API-STU-014`).** Sau khi claim idempotency, lấy advisory lock theo `studyUserId`; đọc active period bằng partial index; kiểm onboarding, target published version và `now >= next_switch_allowed_at`. Nếu có active period, update đúng `version` sang `SWITCHED_OUT`; insert period mới `ACTIVE` và change event, cập nhật path snapshot/outbox trong cùng transaction. Unique partial index là hàng rào cuối cho hai request đồng thời. Không update/delete course enrollment, attempt hay completion.

**Submit assessment (`API-STU-027`).** Khóa cặp learner-assessment; xác nhận access exact version, attempt limit, draft/version và subtype payload. Với file, join asset bằng owner + state `CLEAN` + checksum và attach atomically. Cấp `attemptNo`, copy payload thành snapshot immutable, seal draft. Quiz chấm trong transaction từ answer key immutable; loại còn lại insert review queue. Notification/evidence chạy qua outbox sau commit.

**Publish (`API-STU-056`).** Khóa stable entity và draft. Check report phải thuộc đúng content hash, chưa quá 30 phút, rights còn hiệu lực và mọi asset vẫn CLEAN. Swap current pointer và supersede bản cũ trong một transaction. Enrollment cũ vẫn pin version cũ; không auto-migrate progress.

### 5.4 Transaction application và snapshot

`API-WRK-023` không phụ thuộc tính sẵn sàng của Study. Trong một Work transaction, hệ thống:

1. Claim `Idempotency-Key`, advisory-lock `(candidateId, jobId)` và kiểm unique application.
2. Khóa job current revision; chỉ nhận `PUBLISHED`, chưa hết hạn/closed và revision từ form vẫn current.
3. Kiểm CV revision thuộc candidate và `PUBLISHED`; copy JSON đã sanitize cùng checksum vào snapshot append-only. Copy profile/portfolio đã chọn và job revision; snapshot không theo thay đổi sau này.
4. Tạo application `SUBMITTED`, history đầu tiên, câu trả lời, consent version, từng selected evidence `{studyEvidenceId, expectedVersion, status=PENDING}` và export request.
5. Insert outbox `work.application.submitted` và `work.study_evidence.export_requested`; commit rồi trả application ngay.
6. Worker gửi signed request. Study outage/retry khiến evidence tiếp tục `PENDING`, hết retry chuyển `UNAVAILABLE`; **không** thay đổi ATS/match/rank. Khi consent bị rút, Work chặn mọi read trước khi worker hoàn tất.

## 8. Billing, payment, entitlement và promotion

### 8.1 Nguyên tắc

- V1 bán gói/credit trả trước bằng VND cho Student và Enterprise qua VNPAY và MoMo; không auto-renew, không lưu dữ liệu thẻ, không ví nội bộ, escrow hay payout.
- Webhook/IPN có chữ ký hợp lệ là nguồn xác nhận. Return URL chỉ hiển thị trạng thái đã biết rồi poll order; không cấp entitlement.
- Adapter bám tài liệu chính thức [VNPAY](https://sandbox.vnpayment.vn/apis/docs/thanh-toan-pay/pay.html) và [MoMo](https://developers.momo.vn/v3/docs/payment/api/credit/onetime/). Raw payload được mã hóa/giới hạn quyền và lưu hash + trường cần đối soát.
- Payment order, attempt, webhook, ledger, refund, chargeback, entitlement grant/consume và promotion impression/click là append-only hoặc có append-only history. Số tiền settled phải khớp order; mismatch chuyển review, không cấp quyền.

## 13. Security, privacy và failure contract

- Input được schema-validate, giới hạn kích thước/depth, reject unknown fields ở mutation. Rich text sanitize allowlist; URL chỉ HTTPS và không server-side fetch; SQL dùng parameter binding; object key do server sinh.
- Download URL tối đa 5 phút, một principal/purpose; endpoint re-authorize mỗi lần. MIME sniff + checksum + ClamAV trước CLEAN. `INFECTED/SCAN_FAILED/PENDING` không thể attach/download/review.
- Cross-tenant IDOR test bắt buộc với mọi resource tenant. Service bỏ qua tenant ID ở body; lookup luôn gồm membership context. Mass assignment bị chặn bằng DTO allowlist.
- PII được phân loại, encrypt at rest/field-level khi cần, redact log, audit read đặc quyền. Deletion grace 30 ngày; legal hold ngăn purge nhưng không khôi phục quyền truy cập thông thường.
- Identity unavailable: token đang valid có thể kiểm offline tối đa JWKS/cache TTL nhưng action high-risk fail-closed; projection gap reconcile. Study unavailable không rollback application/evidence request. Redis unavailable: rate limit fail-safe cho auth, cache bypass cho catalog, queue outbox vẫn nằm PostgreSQL. Worker unavailable: API nhận mutation đã commit, biểu diễn `PENDING`, alert backlog. AI unavailable: workflow manual. Payment unavailable: order pending/retry, không entitlement.
- Audit không chứa password/token/raw CV/chat/evidence; ghi actor, effective permission, tenant, action, target, before/after redacted hash, reason, trace/IP/device coarse. Break-glass luôn alert và hết hạn tự động.

## 15. API acceptance cases

1. Register duplicate, verify expired/used, login locked/suspended, MFA invalid, two refresh concurrent/reuse và logout-all đều có response không lộ bí mật.
2. Learner verified chưa onboarding enroll/học standalone thành công; primary-path selection trả `ONBOARDING_REQUIRED`. Hai switch đồng thời chỉ một active; switch trước 168 giờ trả exact `nextAllowedAt`; progress/attempt giữ nguyên và chỉ reuse đúng course version.
3. Hai enrollment/attempt/review/publish/apply cùng lúc tuân unique/lock/idempotency; retry cùng key trả cùng response, khác payload trả `IDEMPOTENCY_KEY_REUSED`.
4. Published version immutable; enrollment/job application snapshot không đổi khi publish revision mới. File MIME spoof/infected/scan-failed/signed URL hết hạn đều bị chặn.
5. Candidate opt-out bị loại khỏi API ngay và search index trong 5 phút; recruiter không thấy contact/CV/evidence từ search. Invitation không tạo application hoặc chat.
6. Apply vẫn thành công khi Study down; evidence chuyển PENDING rồi READY/UNAVAILABLE; lỗi không đổi match/ATS. Consent withdrawal/revocation ẩn snapshot nhưng giữ audit.
7. Cross-tenant enterprise/university IDs trả 404/403 an toàn; member bị revoke mất quyền ngay. Report university cell `<10` bị suppress.
8. Webhook VNPAY/MoMo signature sai không đổi state; duplicate/out-of-order/mismatch đúng invariant; return URL không cấp entitlement; refund/chargeback append ledger và điều chỉnh quyền có audit.
9. AI prompt injection, excluded fields, malformed output, provider timeout và kill switch đi manual path; AI không thể gọi ATS transition/reject/hire. Sponsored luôn có label và không đổi organic/match score.
10. Identity/Study/Redis/worker/provider unavailable, retry/DLQ/reconcile/notification dedupe được quan sát bằng trace/outbox metric; p95 và SLO trong tài liệu tổng quan là quality gate.
