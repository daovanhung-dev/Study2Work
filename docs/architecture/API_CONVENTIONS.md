# API Conventions

## Envelope

Success:

```json
{
  "success": true,
  "businessCode": "SYSTEM_HEALTH_LIVE",
  "message": "Service is live.",
  "data": {},
  "meta": {},
  "traceId": "uuid"
}
```

Error:

```json
{
  "success": false,
  "businessCode": "SYSTEM_INTERNAL_ERROR",
  "message": "Internal server error.",
  "data": null,
  "meta": {
    "fieldErrors": []
  },
  "traceId": "uuid"
}
```

Rules:

- `businessCode` is stable and machine-readable.
- `message` is safe for clients.
- `traceId` is camelCase and mirrors `X-Trace-Id`.
- `meta.pagination` appears only for list responses.
- Error responses set `data` to `null`; field-level details, when safe to
  disclose, are stored in `meta.fieldErrors`.
- Production errors must not expose stack traces.

## Endpoints

| Runtime | Public prefix | Health |
|---|---|---|
| Study API | `/api/v1` | `/health/live`, `/health/ready` |
| Work API | `/api/v1` | `/health/live`, `/health/ready` |
| Internal integration | `/internal/v1` | service-to-service only |

## Headers

- `X-Trace-Id`: accepted from callers when valid; otherwise generated by the API.
- `Idempotency-Key`: required by retryable mutation contracts.
- Study to Work events use `X-S2W-Event-Id`, `X-S2W-Event-Type`, `X-S2W-Signature`, and `X-Correlation-Id`.
