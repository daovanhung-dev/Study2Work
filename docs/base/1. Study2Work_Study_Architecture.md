## 1. Mô tả hệ thống

### 1.1. Tổng quan

**Study2Work** là hệ sinh thái hỗ trợ người học Việt Nam tiếp cận, học tập và phát triển kỹ năng lập trình theo lộ trình thực tế.

Hệ thống gồm **02 hệ thống con độc lập**, mỗi hệ thống có frontend, backend, endpoint và API riêng:

| Hệ thống con | Mục tiêu chính | Ghi chú |
|---|---|---|
| **Study** | Cung cấp khóa học miễn phí và lộ trình học IT | Phạm vi tài liệu hiện tại |
| **Work** | Hỗ trợ định hướng nghề nghiệp, cơ hội việc làm và kết nối thực tế | Thiết kế ở tài liệu DD riêng |

### 1.2. Đối tượng sử dụng

- Sinh viên ngành Công nghệ Thông tin.
- Người mới bắt đầu học lập trình.
- Người bị mất gốc kiến thức lập trình.
- Người muốn chuyển ngành hoặc tìm hiểu về lĩnh vực IT.
- Người cần một lộ trình học tập rõ ràng, miễn phí và phù hợp với thị trường Việt Nam.

### 1.3. Điểm mạnh định hướng

- Miễn phí trong giai đoạn đầu.
- Tập trung hỗ trợ người mất gốc và người mới học.
- Phát triển theo hướng cộng đồng, chia sẻ kiến thức.
- Ưu tiên nội dung, ngôn ngữ và lộ trình phù hợp với người Việt Nam.
- Tách Study và Work thành các hệ thống con độc lập để dễ mở rộng, triển khai và bảo trì.

# 2. Hệ thống con Study

## 2.1. Tổng quan

**Study** là hệ thống học tập trực tuyến, chuyên cung cấp các khóa học IT miễn phí cho sinh viên và người có nhu cầu học hoặc tìm hiểu về lập trình.

Mục tiêu của Study:

- Cung cấp lộ trình học rõ ràng cho từng nhóm người học.
- Hỗ trợ người mất gốc xây lại nền tảng.
- Tạo môi trường học tập có cấu trúc, dễ theo dõi tiến độ.
- Hỗ trợ cộng đồng chia sẻ tài liệu, kiến thức và kinh nghiệm.
- Tạo nền tảng để người học chuyển tiếp sang hệ thống Work sau khi có kiến thức và kỹ năng phù hợp.

## 2.2. Công nghệ và kiến trúc dự án

### 2.2.1. Frontend

#### A. Mục tiêu kiến trúc frontend

Frontend được thiết kế theo hướng:

- Dễ mở rộng khi số lượng khóa học, bài học, lộ trình và module tăng.
- Dễ bảo trì khi nhiều lập trình viên cùng phát triển.
- Phân tách rõ UI, business logic, API và state.
- Hạn chế code trùng lặp.
- Dễ test.
- Có thể tái sử dụng kiến trúc cho hệ thống Work trong tương lai.
- Phù hợp để xây dựng dashboard, cổng học tập, quản trị nội dung và hệ thống cộng đồng.

#### B. Công nghệ đề xuất

| Nhóm | Công nghệ | Vai trò |
|---|---|---|
| Core | Vue 3 | Xây dựng giao diện SPA |
| Ngôn ngữ | TypeScript | Kiểm soát kiểu dữ liệu và giảm lỗi runtime |
| Build tool | Vite | Khởi tạo, build và phát triển frontend |
| Routing | Vue Router | Điều hướng, route guard và URL state |
| Global client state | Pinia | User hiện tại, quyền, theme, sidebar |
| Server state | TanStack Query Vue | Fetch, cache, refetch, mutation và pagination |
| HTTP client | Axios | Gọi API, interceptor, timeout, error handling |
| Validation | Zod | Kiểm tra dữ liệu form và dữ liệu runtime |
| UI | Vuetify hoặc Tailwind CSS | Xây dựng UI theo định hướng sản phẩm |
| Unit test | Vitest | Test utility, composable và business rule |
| E2E test | Playwright | Test luồng người dùng trên trình duyệt |
| Code quality | ESLint + Prettier | Giữ code nhất quán |
| Deployment | Docker + Nginx + CI/CD | Build, triển khai và vận hành |

> **Khuyến nghị UI:** Dùng **Vuetify** cho khu vực quản trị, dashboard và nhiều form/bảng. Dùng **Tailwind CSS** cho landing page, trang public và UI cần thiết kế linh hoạt. Không sử dụng cả hai trong cùng một module nếu không có quy ước rõ ràng.

#### C. Kiến trúc tổng thể

Frontend sử dụng:

```text
Feature-first + Layered Architecture
```

Trong đó:

- **Feature-first:** Chia code theo chức năng nghiệp vụ.
- **Layered Architecture:** Mỗi chức năng có các tầng rõ ràng.
- **App layer:** Chứa cấu hình cấp ứng dụng.
- **Page layer:** Chứa các màn hình gắn với URL.
- **Feature layer:** Chứa nghiệp vụ người dùng có thể thực hiện.
- **Entity layer:** Chứa model nghiệp vụ dùng lại giữa nhiều feature.
- **Shared layer:** Chứa thành phần dùng chung, không phụ thuộc nghiệp vụ.

Luồng phụ thuộc bắt buộc:

```text
App
 ↓
Pages
 ↓
Features
 ↓
Entities
 ↓
Shared
```

Không được import ngược chiều.

Ví dụ luồng lấy danh sách khóa học:

```text
CoursesPage
 ↓
CourseListContainer
 ↓
useCoursesQuery
 ↓
courseApi
 ↓
httpClient
 ↓
Study Backend API
```

#### F. API Layer

Component không được gọi Axios trực tiếp.

Không nên:

```ts
const response = await axios.get('/courses')
```

Nên tách API theo feature:

```ts
import { http } from '@/shared/api/http'
import type {
  CourseListParams,
  CourseListResponse,
  CourseResponse,
} from '../types/course.types'

export const courseApi = {
  async getList(params: CourseListParams): Promise<CourseListResponse> {
    const response = await http.get<CourseListResponse>('/courses', {
      params,
    })

    return response.data
  },

  async getBySlug(slug: string): Promise<CourseResponse> {
    const response = await http.get<CourseResponse>(`/courses/${slug}`)

    return response.data
  },

  async enroll(courseId: string): Promise<void> {
    await http.post(`/courses/${courseId}/enroll`)
  },
}
```

HTTP client dùng chung:

```ts
import axios from 'axios'

export const http = axios.create({
  baseURL: import.meta.env.VITE_STUDY_API_URL,
  timeout: 15_000,
  withCredentials: true,
})
```

HTTP client là nơi chịu trách nhiệm:

- Base URL theo môi trường.
- Timeout.
- Default headers.
- Interceptor request/response.
- Refresh token hoặc logout khi hết phiên.
- Chuẩn hóa API error.
- Cấu hình upload file.

#### H. Pinia

Pinia chỉ dùng cho global client state hoặc shared UI state thực sự cần dùng xuyên page.

Nên dùng Pinia cho:

- User hiện tại.
- Permissions.
- Theme.
- Language.
- Sidebar state.
- Notification unread count.
- App initialization state.

Không nên dùng Pinia cho:

- Danh sách khóa học có pagination.
- Danh sách bài học.
- Course detail response.
- Learning progress response.
- Search result từ backend.

Các dữ liệu đến từ backend nên dùng TanStack Query.

Ví dụ auth store:

```ts
import { computed, ref } from 'vue'
import { defineStore } from 'pinia'

import type { CurrentUser } from '../types/auth.types'
import { authApi } from '../api/auth.api'

export const useAuthStore = defineStore('auth', () => {
  const user = ref<CurrentUser | null>(null)
  const permissions = ref<string[]>([])
  const isInitialized = ref(false)

  const isAuthenticated = computed(() => user.value !== null)

  function hasPermission(permission: string): boolean {
    return permissions.value.includes(permission)
  }

  async function loadCurrentUser() {
    try {
      const response = await authApi.getCurrentUser()

      user.value = response.user
      permissions.value = response.permissions
    } catch {
      user.value = null
      permissions.value = []
    } finally {
      isInitialized.value = true
    }
  }

  function clearSession() {
    user.value = null
    permissions.value = []
    isInitialized.value = true
  }

  return {
    user,
    permissions,
    isInitialized,
    isAuthenticated,
    hasPermission,
    loadCurrentUser,
    clearSession,
  }
})
```

#### I. TanStack Query

TanStack Query quản lý server state:

- Fetch data.
- Loading state.
- Error state.
- Cache.
- Refetch.
- Pagination.
- Mutation.
- Cache invalidation.

Ví dụ lấy danh sách khóa học:

```ts
import { computed, type Ref } from 'vue'
import { useQuery } from '@tanstack/vue-query'

import { courseApi } from '../api/course.api'
import type { CourseListParams } from '../types/course.types'

export function useCoursesQuery(params: Ref<CourseListParams>) {
  return useQuery({
    queryKey: computed(() => ['courses', params.value]),
    queryFn: () => courseApi.getList(params.value),
    staleTime: 30_000,
  })
}
```

Ví dụ đăng ký khóa học:

```ts
import { useMutation, useQueryClient } from '@tanstack/vue-query'

import { courseApi } from '../api/course.api'

export function useEnrollCourseMutation() {
  const queryClient = useQueryClient()

  return useMutation({
    mutationFn: (courseId: string) => courseApi.enroll(courseId),

    async onSuccess(_, courseId) {
      await queryClient.invalidateQueries({
        queryKey: ['courses', courseId],
      })

      await queryClient.invalidateQueries({
        queryKey: ['my-learning'],
      })
    },
  })
}
```

```text

 ↓
```

Ví dụ route:

```ts
{
  path: '/admin/courses',
  name: 'admin-courses',
  component: () => import('@/pages/admin/AdminCoursesPage.vue'),

    requiresAuth: true,
    permissions: ['course.manage'],
    layout: 'admin',

}
```

Ví dụ route guard:

```ts
router.beforeEach(async (to) => {
  const authStore = useAuthStore()

  if (!authStore.isInitialized) {
    await authStore.loadCurrentUser()
  }

  if (to.meta.requiresAuth && !authStore.isAuthenticated) {
    return {
      name: 'login',
      query: {
        redirect: to.fullPath,
      },
    }
  }

  const permissions = to.meta.permissions as string[] | undefined

  if (
    permissions?.length &&
    !permissions.every(authStore.hasPermission)
  ) {
    return {
      name: 'forbidden',
    }
  }
})
```

> Frontend guard chỉ kiểm soát trải nghiệm điều hướng. Backend phải xác thực và phân quyền tại từng API endpoint.

#### K. Zod và Form Validation

TypeScript không kiểm tra dữ liệu runtime. Zod dùng để validate dữ liệu người dùng nhập, query params hoặc dữ liệu nhận từ bên ngoài.

Ví dụ schema tạo khóa học:

```ts
import { z } from 'zod'

export const createCourseSchema = z.object({
  title: z
    .string()
    .trim()
    .min(5, 'Tên khóa học phải có ít nhất 5 ký tự')
    .max(150, 'Tên khóa học tối đa 150 ký tự'),

  description: z
    .string()
    .trim()
    .min(20, 'Mô tả khóa học phải có ít nhất 20 ký tự'),

  level: z.enum(['beginner', 'intermediate', 'advanced']),

  categoryId: z
    .string()
    .uuid('Danh mục không hợp lệ'),
})

export type CreateCourseInput = z.infer<typeof createCourseSchema>
```

Quy tắc:

- Form lớn hoặc nhiều field: dùng Zod kết hợp VeeValidate.
- Payload gửi API: validate trước khi submit.
- Query params phức tạp: validate và normalize.
- API response quan trọng hoặc từ dịch vụ bên thứ ba: cân nhắc validate runtime.

#### L. TypeScript Rules

Bật strict mode:

```json
{
  "compilerOptions": {
    "strict": true,
    "noImplicitAny": true,
    "noUncheckedIndexedAccess": true
  }
}
```

Không dùng `any` tràn lan.

Không nên:

```ts
const data: any = response.data
```

Ưu tiên:

```ts
const data: unknown = response.data
```

Sau đó validate hoặc narrow type trước khi sử dụng.

Ví dụ:

```ts
function getErrorMessage(error: unknown): string {
  if (error instanceof Error) {
    return error.message
  }

  return 'Đã có lỗi không xác định.'
}
```

#### A. Mục tiêu kiến trúc backend

Backend của hệ thống **Study** được xây dựng theo hướng:

```text
Modular Monolith
+ Feature-first
+ Clean Architecture
+ DDD-lite
```

Mục tiêu chính:

- Tổ chức code theo module nghiệp vụ, không theo các thư mục kỹ thuật chung quá lớn như `models/`, `services/` hoặc `routers/`.
- Tách rõ HTTP API, nghiệp vụ, dữ liệu và tích hợp hệ thống ngoài.
- Dễ phát triển bởi team nhỏ ở giai đoạn đầu nhưng vẫn đủ cấu trúc để mở rộng.

- Dễ viết unit test, integration test và API test.
- Có thể tách module thành service độc lập trong tương lai khi thật sự cần thiết, mà không phải viết lại toàn bộ hệ thống.
- Cung cấp OpenAPI contract ổn định để frontend Vue 3 có thể sinh TypeScript API client tự động.

> **Quyết định kiến trúc:** Study khởi đầu dưới dạng **một backend deployable duy nhất**. Không tách microservice sớm vì điều đó làm tăng chi phí vận hành, logging, giao tiếp nội bộ, transaction và debug. Module chỉ được tách thành service khi có lý do rõ ràng về tải, quyền sở hữu team hoặc yêu cầu triển khai độc lập.

#### E. Feature-first + Clean Architecture

Backend kết hợp hai nguyên tắc:

```text
Feature-first
+ Clean Architecture
```

**Feature-first**: chia theo nghiệp vụ như `courses`, `lessons`, `enrollments`, `community`.

**Clean Architecture**: mỗi nghiệp vụ được chia thành các tầng có trách nhiệm rõ ràng:

```text
Presentation Layer
        ↓
Application Layer
        ↓
Domain Layer
        ↑
Infrastructure Layer
```

Quy tắc phụ thuộc:

```text
Presentation → Application → Domain
Infrastructure → Domain
```

Giải thích:

- `Presentation` biết HTTP, FastAPI, request, response và dependency.
- `Application` điều phối use case, transaction và luồng nghiệp vụ.
- `Domain` chứa entity, business rule, repository interface và domain exception.
- `Infrastructure` biết PostgreSQL, SQLAlchemy, Redis, email, storage, AI hoặc external API.
- `Domain` không được phụ thuộc vào FastAPI, SQLAlchemy, Redis hoặc HTTP.

Các phụ thuộc không hợp lệ:

```text
Domain → FastAPI
Domain → SQLAlchemy
Domain → HTTPException
Domain → Request / Response
Router → SQL query trực tiếp
Router → commit transaction trực tiếp
```

#### H. Giải thích chi tiết các tầng

##### 1. Presentation Layer

Presentation Layer là nơi backend tiếp xúc với client qua HTTP.

Bao gồm:

```text

Request schema
Response schema
Dependency injection
Authentication dependency
Permission dependency
HTTP status code
```

Trách nhiệm:

- Nhận request.
- Validate input bằng Pydantic.
- Lấy user hiện tại từ access token.
- Kiểm tra quyền gọi API.
- Gọi use case.
- Chuyển DTO thành response HTTP chuẩn.

Presentation Layer không được:

```text
Không viết SQL query trực tiếp.
Không gọi SQLAlchemy session trực tiếp trong router.
Không chứa business rule phức tạp.
Không tự commit hoặc rollback transaction.
Không trả ORM Model trực tiếp ra API.
```

Ví dụ không nên dùng:

```python
@router.post("/")
async def create_course(data: CreateCourseRequest, session: AsyncSession):
    course = CourseModel(**data.model_dump())
    session.add(course)
    await session.commit()
    return course
```

Ví dụ theo kiến trúc đề xuất:

```python
@router.post("/", status_code=201, response_model=ApiResponse[CourseResponse])
async def create_course(
    data: CreateCourseRequest,
    current_user: CurrentUser = Depends(require_permission("course.create")),
    use_case: CreateCourseUseCase = Depends(get_create_course_use_case),
):
    result = await use_case.execute(data=data, actor=current_user)
    return success_response(data=result, message="Course created successfully")
```

```python
class SqlAlchemyCourseRepository:
    def __init__(self, session: AsyncSession) -> None:
        self._session = session

    async def get_by_id(self, course_id: UUID) -> Course | None:
        result = await self._session.execute(
            select(CourseModel).where(CourseModel.id == course_id)
        )
        model = result.scalar_one_or_none()
        return CourseMapper.to_entity(model) if model else None
```

Application Layer phụ thuộc `CourseRepository` interface, không phụ thuộc trực tiếp `SqlAlchemyCourseRepository`.

#### K. Transaction và Unit of Work

Mỗi use case có thay đổi dữ liệu phải chạy trong transaction rõ ràng.

Ví dụ:

```text
Tạo enrollment
→ lưu enrollment
→ tạo progress ban đầu
→ ghi audit log
→ commit
```

Nếu bất kỳ bước nào thất bại:

```text
Rollback toàn bộ transaction.
```

Nguyên tắc:

```text
Repository không tự commit.
Use case hoặc Unit of Work quyết định commit / rollback.
Một hành động nghiệp vụ có nhiều thao tác ghi phải được bảo vệ bởi một transaction.
```

Ví dụ:

```python
async with unit_of_work:
    await enrollment_repository.add(enrollment)
    await progress_repository.create_for_enrollment(enrollment.id)
    await audit_log_repository.add(audit_log)
    await unit_of_work.commit()
```

Tác vụ ngoài transaction như gửi email, push notification hoặc gọi AI không nên làm block request. Chúng được đưa vào worker sau khi dữ liệu chính đã commit thành công.

#### M. Authentication và Authorization

##### Authentication

Luồng đăng nhập đề xuất:

```text
Email + Password
→ verify password hash
→ tạo access token ngắn hạn
→ tạo refresh token dài hạn
→ client sử dụng access token khi gọi API
→ refresh token dùng để làm mới phiên
```

Header chuẩn:

```text
Authorization: Bearer <access_token>
```

Khuyến nghị bảo mật:

- Password phải hash bằng Argon2 hoặc bcrypt.
- Không lưu password dạng plain text.
- Refresh token nên lưu bằng `HttpOnly`, `Secure`, `SameSite` cookie khi kiến trúc domain cho phép.
- Access token cần thời hạn ngắn.
- Token bị thu hồi hoặc logout có thể quản lý bằng Redis blacklist hoặc token version.
- Khi dùng cookie cho xác thực, cần bổ sung biện pháp chống CSRF phù hợp.
- Không lưu refresh token trong `localStorage` theo mặc định.

##### Authorization

Phân quyền theo **RBAC + Permission**.

Ví dụ role:

```text
Guest
Student
Mentor
ContentManager
Admin
```

Ví dụ permission:

```text
course.create
course.update.own
course.publish
lesson.manage
enrollment.read.own
progress.update.own
community.moderate
user.manage
system.manage
```

Luồng kiểm tra quyền:

```text
Request
→ verify JWT
→ lấy current user
→ lấy permissions
→ kiểm tra quyền endpoint yêu cầu
→ allow hoặc deny
```

Frontend route guard chỉ cải thiện trải nghiệm người dùng. Backend phải kiểm tra authentication và authorization tại mọi endpoint nhạy cảm.

Quy tắc:

- Không commit `.env`.
- Có `.env.example` không chứa secret thật.
- Tách cấu hình `development`, `staging`, `production`.
- Bật CORS theo whitelist domain cụ thể, không để `*` ở production khi sử dụng credentials.
- Có backup và restore plan cho PostgreSQL và object storage trước khi triển khai production.

#### V. Quy tắc code backend bắt buộc

```text
1. Router không query database trực tiếp.
2. Router không chứa business logic phức tạp.
3. Repository không tự commit transaction.
4. Use case là nơi điều phối transaction và nghiệp vụ.
5. Domain không phụ thuộc FastAPI, SQLAlchemy, Redis hoặc HTTP.

7. Mọi thay đổi database phải có Alembic migration.
8. Mọi endpoint nhạy cảm phải kiểm tra authentication và permission ở backend.
9. API list phải có pagination; filter/search/sort được bổ sung khi phù hợp.
10. Tác vụ lâu hoặc cần retry phải chạy qua background worker.
11. Không dùng một service.py khổng lồ cho toàn module.
12. Không tạo utils/ chung chứa business logic không rõ chủ sở hữu.
13. Shared layer không được phụ thuộc module nghiệp vụ.
14. Không log password, token, secret hoặc dữ liệu nhạy cảm.
15. Mọi module mới phải có test cho rule nghiệp vụ quan trọng.
16. Mọi API contract thay đổi phải được đánh giá ảnh hưởng tới OpenAPI client của frontend.
```

Trước thời điểm đó, Modular Monolith vẫn là kiến trúc tối ưu vì đơn giản hơn để phát triển, debug, transaction và triển khai.
